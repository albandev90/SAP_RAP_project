# SAP_RAP_project

Учебно-практический проект на **SAP RAP (RESTful ABAP Programming Model)**, демонстрирующий, как строить современное бизнес-приложение в ABAP с четким разделением слоев: модель данных, поведение (business logic) и сервис (OData).

## О проекте

`SAP_RAP_project` — это пример RAP-приложения, в котором реализуется типичный CRUD-сценарий для бизнес-сущностей через OData-сервис.

Проект показывает современный подход в SAP backend-разработке:
- описание данных через CDS,
- декларативное и управляемое поведение через Behavior Definition/Implementation,
- публикация через service definition/binding,
- готовность к использованию из Fiori/UI-клиентов и интеграций.

Если коротко: проект отвечает на вопрос **«как правильно собирать backend на RAP от таблицы до API»**.

## Ключевые технологии

### 1) ABAP
Основной язык реализации серверной логики:
- обработка бизнес-правил,
- валидации,
- determinations/actions (в зависимости от сценария),
- техническая логика для CRUD-операций.

### 2) ABAP CDS (Core Data Services)
Используется для моделирования данных и проекций:
- декларативное описание сущностей,
- связи между сущностями (associations/compositions),
- аннотации для сервисного и UI-поведения.

### 3) SAP RAP
Ключевая архитектурная основа:
- **Data Model Layer** (таблицы + CDS),
- **Behavior Layer** (что можно делать с сущностью и какие правила применяются),
- **Service Layer** (как это публикуется наружу).

### 4) OData (через Service Binding)
Внешний контракт приложения:
- стандартный REST-подобный доступ к данным,
- интеграция с SAP Fiori Elements и внешними потребителями API.

## Как это работает (архитектурно)

Ниже типичный поток, который реализуется в RAP-проекте:

1. **Persistency**  
   Базовые таблицы/структуры хранят данные предметной области.

2. **CDS View Entity**  
   Поверх persistency создаются CDS-сущности, которые задают бизнес-модель данных.

3. **Behavior Definition (BDEF)**  
   Описывает, какие операции доступны:
   - create / update / delete,
   - draft/active (если используется draft),
   - validations/determinations/actions.

4. **Behavior Implementation (ABAP class)**  
   Реальная реализация поведения:
   - проверка бизнес-ограничений,
   - автоматические вычисления,
   - контроль консистентности данных.

5. **Service Definition + Service Binding**  
   Публикация сущностей как OData-сервиса для UI/интеграции.

## Что разработчик получает на выходе

- Единый источник правды по модели данных через CDS.
- Централизованную бизнес-логику в Behavior-слое.
- Понятный API-контракт через OData.
- Хорошую расширяемость и поддержку по сравнению с классическими “монолитными” ABAP-реализациями.

## Для кого этот проект

Проект будет полезен:
- ABAP-разработчикам, переходящим на RAP,
- backend-разработчикам SAP, которым нужен рабочий шаблон структуры RAP-приложения,
- разработчикам уровня **middle**, которые уже знают базовый ABAP/CDS и хотят увидеть целостную реализацию.

## Практическая ценность

На основе этого проекта можно:
- быстро стартовать новый RAP-сервис под свою предметную область,
- использовать структуру как reference architecture,
- адаптировать behavior-логику под реальные бизнес-процессы (валидации, действия, вычисления, статусы и т.д.).

## Возможные направления развития

- Добавить более сложные actions (approve/reject/post и т.п.).
- Расширить валидации и determinations.
- Включить/расширить draft-сценарий.
- Подключить Fiori Elements UI и оформить end-to-end поток.
- Добавить тестирование и проверку бизнес-правил.

## Итог

`SAP_RAP_project` — это демонстрация современного SAP backend-подхода на RAP:  
**CDS-модель + управляемое поведение + OData-сервис**.  

Проект хорошо подходит как “рабочий каркас” и как учебный пример для разработчика уровня middle, которому важно понять не только синтаксис, но и правильную архитектурную сборку RAP-приложения.
